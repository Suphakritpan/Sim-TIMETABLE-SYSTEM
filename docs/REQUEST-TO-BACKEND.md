## A. สิ่งที่ต้องส่งกลับมา (เรียงตามความเร่งด่วน)

> ส่งเป็นไฟล์/ข้อความที่คัดลอกได้ ห้ามสรุปย่อ ห้ามเขียนใหม่ด้วยความจำ ให้ดึงจากโค้ดหรือรันจริง

### A1. `openapi.json` ฉบับจริง (ชั่วโมงแรก)
รันจากโปรเจกต์ Backend (ปรับ path โมดูลให้ตรงของจริง) และแนบไฟล์:
```bash
python - <<'PY'
import json
from app.main import app          # ← ปรับให้ตรงโมดูลจริงของ template
print(json.dumps(app.openapi(), ensure_ascii=False, indent=2))
PY
```
แนบ `openapi.json` ทั้งไฟล์ ไม่ตัดทอน (ครอบคลุมทั้ง 18 endpoint ใน template และของใหม่ที่เพิ่มแล้ว)

### A2. ตาราง endpoint ปัจจุบัน + แผน F1
ตาราง Markdown ทุก endpoint **ที่จะอยู่ใน production ตอนส่งงาน** คอลัมน์: `method | path | หน้าที่ | ต้องล็อกอินไหม | request (ชื่อฟิลด์/ชนิด) | response สำเร็จ | response ผิดพลาด (code/HTTP)` โดยเฉพาะ:
- อัปโหลด+ตรวจไฟล์ Excel, อ่านข้อมูลที่นำเข้า
- ตีความคำขอพิเศษ (ทั้งข้อความที่มีอยู่ในไฟล์และข้อความใหม่)
- เริ่มจัดตาราง (รับ `seed`, วิธี baseline/team, คำขอพิเศษที่ยืนยันแล้ว)
- ดูสถานะ/ผล, ยกเลิก, SSE ความคืบหน้า
- เปรียบเทียบ (`/api/comparisons` และ `/api/comparisons/latest`) และ `/api/runs` — อธิบายว่าต่างจาก jobs อย่างไร
- ส่งออก PDF/Excel
- ตัดสินให้ชัด: endpoint ไหนของ template (`auth/*`, `me`, `users`, `documents`, `admin`) **จะถูกลบ** และเมื่อไร
- แนบหัวข้อ 6 ของ `docs/SPEC.md` ทั้งหัวข้อ (สำเนาตรงตัว)

### A3. ตัวอย่าง response จริง (JSON) — สร้างจากชุดทดลอง `2_…4กลุ่ม.xlsx`
ไฟล์แยกตามนี้ (เรียกด้วยตัว API จริงหรือรันฟังก์ชันจริง ไม่เขียนเอง):

| ไฟล์ | สถานการณ์ |
|---|---|
| `imports-valid.json` | อัปโหลดชุดทดลองถูกต้อง (มี summary จำนวนครู/ห้อง/กลุ่ม/รายการสอน) |
| `imports-invalid.json` | ไฟล์ที่ใส่ข้อมูลผิดหลายจุดตั้งใจ (รหัสครูซ้ำ, กลุ่มที่ไม่มีห้องจุพอ, ขาดแผ่นงาน/คอลัมน์) — ต้องแสดง **ทุกจุดในครั้งเดียว** พร้อมแผ่นงาน/แถว/ผิดอะไร/แก้อย่างไร |
| `requests-interpreted.json` | ตีความคำขอพิเศษทุกข้อในชุดทดลองและชุดหลัก (3 ประเภท: ต้องทำ / ทำถ้าทำได้ / ไม่ต้องทำเพิ่ม + `understood` อ่านง่าย) |
| `requests-llm-down.json` | ตอนเรียก LLM ไม่ได้ (fallback ทำงาน/ต้องกรอกผ่านฟอร์ม) |
| `job-created.json` | หลังเริ่มจัดตาราง |
| `job-running-*.json` | ตัวอย่างสถานะระหว่างรัน (ได้ progress/stage แบบที่เป็นจริง ถ้าวัดไม่ได้ให้ `null` ไม่ต้องแต่ง) |
| `job-completed.json` | สำเร็จ: placements ครบ + ผลตรวจ (จัดครบ X/Y, ครู/ห้อง/กลุ่มชน, ผิดกฎอื่น, คะแนนโทษ, วินาที, คำอธิบายว่าจัดวิชาไหนก่อนเพราะอะไร) + summary (ห้องถูกใช้กี่ %, คาบของครูแต่ละคน, คาบว่างของกลุ่ม, ผลคำขอพิเศษทีละข้อ) |
| `job-infeasible.json` | ข้อมูลที่จัดไม่ได้จริง พร้อมเหตุผล (สร้างกรณีทดสอบเอง) |
| `job-cancelled.json` | ยกเลิกกลางคัน |
| `job-failed.json` | ระบบล้มเหลว (error envelope) |
| `comparison-result.json` | เทียบ baseline กับ team บนข้อมูล+seed เดียวกัน (จุดที่ชน, คะแนนโทษ, เวลา + คำอธิบายวิธีของทีมที่ระบุว่าใช้ AI ตรงไหน ตั้งค่าอะไร) |
| `error-*.json` | ตัวอย่าง error ทุกชนิดที่ API คืน (404, 413, 415, 422, 500) |
| `sse-sample.txt` | ข้อความดิบของสตรีม SSE ตั้งแต่เชื่อมต่อจนจบ (รวม heartbeat และ event สุดท้าย) |
| `export-sample.xlsx`, `export-sample.pdf` | ไฟล์ส่งออกจริงจากชุดทดลอง |

กติกาของตัวอย่าง: มาจากข้อมูลจริงชุดทดลอง ไม่ใช่เดา · ผ่าน schema ตัวเดียวกับ API · ห้ามมีข้อมูลบุคคลจริงนอกเหนือไฟล์โจทย์

### A4. ข้อเท็จจริงเกี่ยวกับ SSE และการเชื่อมต่อ
ตอบเป็นข้อ ๆ จากโค้ดจริง: path ของ SSE; ชนิด event และ payload แต่ละชนิด; ส่ง event แรกทันทีเมื่อเชื่อมต่อหรือไม่; รองรับ `Last-Event-ID` หรือไม่; มี heartbeat ไหม (ทุกกี่วินาที); event จบเป็นอย่างไร; ต้องส่ง header อะไรเข้าไปบ้าง (EventSource ใส่ header เองไม่ได้); มี endpoint `GET` สถานะที่ให้ข้อมูลเดียวกันเพื่อใช้เป็น fallback หรือไม่

### A5. สภาพแวดล้อมจริง
- URL Backend ที่เรียกได้จากอินเทอร์เน็ตตอนนี้ (แม้เป็นเวอร์ชันเปล่า) หรือบอกว่ายังไม่มี
- โดเมน/subdomain ที่จะใช้ (หรือยังไม่มี → ดู §D ข้อ 1)
- เวอร์ชัน Python / FastAPI / PostgreSQL / library หลักที่ใช้ (เช่น ตัวแก้ constraint) และเวอร์ชันที่ล็อก
- พอร์ตและชื่อ service ใน `docker-compose.yml`, วิธีรัน (`docker compose up`), ตัวแปร env ที่ต้องตั้งทั้งหมด (ชื่อเท่านั้น **ห้ามส่งค่าจริง/ความลับ**)

## C. คำสั่งตรวจรับ (รันจริงแล้วแนบผลลัพธ์ดิบ)

แทนที่ `API` = `https://api.<domain>` และ `WEB` = origin ของ Vercel (เช่น `https://<project>.vercel.app`)

```bash
# 1) health
curl -i "$API/api/health"

# 2) CORS preflight จาก origin ของเว็บ → ต้องได้ 200/204 และ Access-Control-Allow-Origin = $WEB (ไม่ใช่ *)
curl -i -X OPTIONS "$API/<path-อัปโหลด>" \
  -H "Origin: $WEB" -H "Access-Control-Request-Method: POST" -H "Access-Control-Request-Headers: content-type"

# 3) origin แปลกปลอมต้องไม่ได้รับอนุญาต (ไม่มี Access-Control-Allow-Origin ของ origin นั้น)
curl -i "$API/api/health" -H "Origin: https://evil.example"

# 4) อัปโหลดไฟล์ถูก/ผิด (ผลต้องเป็น summary / รายการข้อผิดครบทุกจุด)
curl -i -F "file=@2_ข้อมูลชุดทดลอง_4กลุ่ม.xlsx" "$API/<path-อัปโหลด>" -H "Origin: $WEB"

# 5) ชนิดไฟล์ผิด / ใหญ่เกิน → 415 / 413 ใน error envelope
curl -i -F "file=@README.md" "$API/<path-อัปโหลด>"

# 6) SSE: ต้องเห็นข้อความทยอยมา (ไม่ถูกบัฟเฟอร์) มี heartbeat และ event สุดท้าย
curl -N -H "Accept: text/event-stream" -H "Origin: $WEB" "$API/<path-SSE>"

# 7) ส่งออก: ต้องมี Content-Disposition และ Access-Control-Expose-Headers มี Content-Disposition
curl -i -H "Origin: $WEB" "$API/<path-export>?format=xlsx" -o out.xlsx
```
แล้วตรวจ `out.xlsx` เทียบกับ `4_ตัวอย่างไฟล์ตารางสอนที่ต้องส่งออก.xlsx` (ชื่อแผ่น, หัวคอลัมน์ 6 ช่อง, ชนิดข้อมูล) · รันชุดทดลองด้วย seed เดิม 2 ครั้ง เปรียบเทียบผลทั้งก้อนต้องเหมือนกัน · ยกเลิกกลางคันแล้วจัดใหม่ · ทดสอบชุดใหญ่

## D. คำถามที่ต้องตอบ (ตอบเป็นข้อ ๆ ห้ามข้าม)

1. **โดเมน:** มี (sub)domain ที่ชี้ VPS แล้วหรือยัง? ถ้ายัง ทดลองใช้ hostname ฟรี (เช่น `<ip>.sslip.io` หรือ DuckDNS) ให้ Caddy ขอใบรับรองได้จริงไหม (ลองจริงแล้วรายงานผล)
2. endpoint จริงที่จะถูกใช้คืออะไร (A2) และ `/api/runs` / `/api/comparisons` ต่างจาก `/api/jobs` อย่างไร
3. วิธีของทีม ("AI" ที่ใช้) คืออะไร ใช้ตรงไหน ตั้งค่าอะไร (ใช้อธิบายหน้า 5 และนำเสนอ) และวิธีพื้นฐานเทียบคืออะไร
4. เวลาที่วัดได้จริง: ชุดทดลอง, ชุดหลัก, ชุดใหญ่ ~600; เวลาที่ยกเลิกได้จริง; progress วัดได้ละเอียดแค่ไหน (`null` ได้ถ้าไม่ได้)
5. LLM ฟรีที่ใช้คือเจ้าไหน/โมเดลอะไร ข้อจำกัดอัตราเรียก และผลทดสอบตีความ
6. ชนิดคำขอพิเศษที่รองรับครบแค่ไหน อะไรที่ตีความไม่ได้ (เพื่อให้เราทำฟอร์ม)
7. โครงสร้างข้อมูลผลตรวจกฎ 10 ข้อ: รหัสแต่ละข้อที่ API คืนคืออะไร
8. อะไรที่ทำไม่ทันภายในวัน → เสนอรายการที่ตัดได้ (ห้ามตัด: ความถูกต้องของกฎ 10 ข้อ, seed เดิมผลเดิม, รูปแบบ Excel, การตรวจข้อมูลนำเข้าให้ครบทุกจุด)
9. มีข้อจำกัดอื่นของ template/VPS ที่เราควรรู้ไหม (RAM/CPU ของ VPS, พอร์ต, การสำรองข้อมูล)
