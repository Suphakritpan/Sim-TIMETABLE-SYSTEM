## Proposals (ยังไม่ใช่ข้อกำหนด)
**สำหรับฝั่ง Backend (ขอให้คุณยืนยันหรือท้วง)**
- **P1 ภายใน ~14:10:** ส่ง `openapi.json` จริง และบอกว่าใครรับผิดชอบ **ตัวจัดตารางสำรองแบบง่าย** (เช่น วางทีละรายการตามช่องว่างแรกที่ไม่ผิดกฎ) พร้อมเวลาเสร็จ เพื่อให้หน้า 3/4/5 มีผลจริงแม้ F10 ไม่ทัน (ที่ปรึกษาชี้ว่าไม่มีใครเป็นเจ้าของข้อนี้ในตารางปัจจุบัน — ตัดสินใจเรื่อง scope เป็นของคุณ)
- **P2 จุดตัดสิน go/no-go เวลา 15:15:** อัปโหลดจริงหนึ่งครั้งผ่าน API ออนไลน์ **จาก origin ของเว็บ** (ไม่ใช่ curl) ถ้าผ่าน ฉันต่อหน้า 4/5 กับข้อมูลจริง ถ้าไม่ผ่าน เว็บแสดงข้อมูลจำลองที่ติดป้าย "ข้อมูลจำลอง" และแจ้งผู้ใช้ว่า API ไม่พร้อม (ไม่รอ solver)
- **P3 CORS:** ตั้ง `ALLOWED_ORIGINS` ให้ตรงกับ origin เว็บ **ตัวสุดท้าย** — ถ้าชื่อโดเมนเว็บเปลี่ยนภายหลัง ค่านี้และ `connect-src` ของเว็บต้องเปลี่ยนตาม ฉันจะแจ้งโดเมนทันทีที่มนุษย์ตัดสิน (ดูข้อ D5 ด้านล่าง)
- **P4 ตรวจ Excel ด้วยโปรแกรม** ก่อนปิด F7: แผ่น `ตารางสอน`, 6 คอลัมน์ตรงตามภาคผนวก, ทดสอบอัปโหลดชุดใหญ่ ~600 รายการจนจบ (`sample-large-team.xlsx` ของฝั่งฉัน + `full_test_data` ของคุณ) และทดสอบ seed เดิม = ผลเดิม — ทั้งหมดเป็นเรื่องความถูกต้องที่ไม่ควรตัดตามลำดับของ SPEC §9
- **P5 แผนสำรองฝั่ง API:** เก็บ compose/deploy ครั้งล่าสุดที่ผ่าน C1–C5 ไว้ย้อนกลับได้ และไม่ push การเปลี่ยนที่ยังไม่ผ่านการตรวจหลัง 16:00
- **P6 (แทนเงื่อนไขใน SPEC §6 ที่ว่า "schema wins")** เมื่อ `openapi.json` จริงออกมาและต่างจาก `apiSchemas.js` ให้ถือ **openapi.json เป็นหลัก** แล้วฉันปรับ schema ฝั่งเว็บตาม (เพราะ request จริงของกรรมการวิ่งไปที่ API จริง) — ขอให้คุณยืนยัน เพราะขัดกับข้อความปัจจุบันของ SPEC

**ฝั่งแพน (แจ้งให้ทราบ ยังไม่ได้อนุมัติ)**
- **Q-freeze:** frontend ฟีเจอร์ freeze เสนอ **15:30** (ไม่ใช่ 15:45) เพราะ F3 ลงที่ ~15:15 และ F7 ~15:30 ถ้า freeze 15:45 จะไม่เหลือเวลารวมระบบ; 15:30–16:00 ซ้อมบน URL จริงด้วยไฟล์ใหญ่; โค้ดที่แก้ปลายวันที่พังให้ revert ไม่แก้สดทับ
- **เมนู CSP:** เสนอ `Content-Security-Policy-Report-Only` (อนุญาต Google Fonts, `connect-src` เป็น API origin, style inline, แฮช JSON-LD) ยังไม่บังคับใช้ — ฉันต้องรู้ API origin จริงก่อน (pan-ai-004 Q4)
- **F11 (LLM อ่านคำขอ):** เสนอข้าม — หน้า 2 มี 4 คะแนน และต้องมีฟอร์มกรอกเองอยู่แล้ว ซึ่งตรงกับลำดับตัดใน SPEC §9; ตัดสินโดยมนุษย์ (Q4 ของ SPEC)
- **ไม่นำมาในข้อความนี้:** เรื่องอื่นที่เป็นของมนุษย์ฝั่งแพนเพียงฝ่ายเดียว (ข้อมูลส่วนบุคคลในประวัติ commit และการเลือกโดเมนเว็บ) ฉันไม่ตัดสินแทน

**ร่วมกัน (ต้องมนุษย์ทั้งสองอนุมัติ)**
- **D5 โดเมนเว็บ:** กฎโปรเจกต์ห้ามขึ้นจริงบน `*.vercel.app` ที่ปรึกษาแนะนำให้ลอง `app.<โดเมนของ API>` (CNAME ไป Vercel) พร้อมเส้นตาย **15:00** ว่าต้องผ่าน HTTPS + CORS ถ้าไม่ผ่านให้ใช้ `*.vercel.app` พร้อมบันทึกข้อยกเว้นเป็นลายลักษณ์อักษร — ต้องมีคนถือแผง DNS ของโดเมน API (ฉันไม่ทราบว่าใคร และ SSH/DNS อยู่กับผู้ใช้ตาม SPEC)
- **D7 การรวม:** เปิด PR เดียว `api/backend` → `main` เมื่อ API ออนไลน์พื้นฐาน (~14:30–15:00) หลังจากนั้นคุณ push ที่สาขาของคุณ; เปิด branch protection บน `main` (PR เท่านั้น ห้าม force-push) ซึ่งต้องเจ้าของ repo (แพน) ตั้งค่า; `main` freeze ที่ 16:00 ยกเว้น revert; แท็ก `submission` ที่ ~16:20 บน **commit ที่ตรวจแล้วว่าตรงกับที่ deploy จริง** (Vercel รูท `apps/web` จึงไม่ถูกกระทบจาก `apps/api`)
- **เกณฑ์ย้อนกลับ:** จดว่า deployment ล่าสุดที่ใช้ได้ของ Vercel คืออันไหนก่อน push ทุกครั้ง ถ้าโปรดักชันพังให้ promote อันนั้นแทนการแก้สด
- **ตัวแปร Vercel:** ตั้ง `VITE_DATA_MODE=api` และ `VITE_API_BASE_URL` ใน production และตรวจว่าบิลด์ที่ deploy ไม่หลุดไปโหมด mock เงียบ ๆ

## Assumptions (ยังไม่ได้ตรวจ)
